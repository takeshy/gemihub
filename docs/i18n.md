# Internationalization / 国際化

[English README](../README.md) · [日本語 README](../README_ja.md)

## Runtime behavior

Supported locales are `ja` and `en`. On the first visit, Japanese-preferring browsers get Japanese; other stated browser languages get English. With no language header the default is Japanese. `?lang=en` and `?lang=ja` are explicit entry points. The switcher reloads the current URL with that parameter, retaining route and other query parameters. Save or finish unsaved work before switching languages. Choosing a language stores `gemihub:locale` in localStorage and `gemihub_locale` in a SameSite=Lax cookie. Storage failures do not block explicit URL selection.

The browser sends `X-Gemihub-Language` with API calls. The server resolves query → header → cookie → preferred browser language → Japanese. The browser resolves explicit query → saved preference → cookie → exported HTML metadata → Japanese. Google OAuth state preserves the initiating language, including callbacks and public-host handoff. The server uses AsyncLocalStorage, never a process-global mutable current language. Background jobs retain their initiating language across retries. Shared code has no Node imports; its server resolver is installed by `server/i18n.ts`.

HTML sets `lang`, API responses set Content-Language, and language-sensitive responses vary by Cookie, X-Gemihub-Language and Accept-Language. Offline exports carry default-language metadata; only valid file:// exports activate the isolated mock API. The public security, authorization, and publication restrictions apply equally in both languages.

The interface does not translate stored user data. Shop names, descriptions, page text, articles, customer information, and saved history retain their entered language. AI proposes new text in the selected language without changing unrelated data. Demo fixture text is translated explicitly. Shop country and time zone are separate from interface language: JP uses integer JPY and Asia/Tokyo; US uses USD with up to two decimal places and one of seven US zones. Business dates, booking slots, filters, notifications and exports follow the shop. Date inputs stay YYYY/MM/DD with ISO UTC API values. Missing region remains JP for compatibility.

Voice recognition uses ja-JP or en-US. English defaults to “send”; Japanese defaults to “以上”. Preferences are separate per language. A completion phrase is not publication or generation approval.

## Adding translations

Use Japanese source keys in `tr("日本語の文言")`, with the English value in `shared/en.json`. `tr` reads the current locale when called. Avoid evaluating translated strings once at module initialization. For shared metadata, use getters or functions so English requests and Storybook toolbar changes get the correct text.

Use numbered placeholders for complete sentences:

```ts
tr("{0}を更新", fieldName)
```

English can reorder placeholders. Arguments are inserted once and are never interpreted as templates or JavaScript. Existing HTML escaping remains required where the result is inserted into HTML. Do not pass user content through translation as a substitute for translating the interface around it.

Zod custom errors use `error: () => tr(...)` to resolve language when validating, rather than when constructing the schema. Do not translate persisted enum values, IDs, paths, schema column names, MIME types, or protocol constants. Japanese regular expressions used to parse Japanese input are not interface strings.

The application dictionary includes UI, server validation, notification templates, generated specification/schema/diagram labels, and AI instructions. Update English prompt translations when changing Japanese instructions, preserving safety and validation constraints.

## Storybook and manual

The globe toolbar selects Japanese or English. An iframe can use `&globals=locale:en`. Its decorator remounts the story to reset fixtures in the chosen language. The explorer displays English/Japanese labels through its manager configuration; index metadata and IDs remain unchanged for existing capture/check scripts.

`src/Manual.tsx` has localized instructions and captions. English assets live in `public/manual/en/`; Japanese assets remain in `public/manual/`. Regenerate them using the commands below. The English capture runner reuses the Japanese interaction script, replacing known labels and sample input, and adds the system/pen screenshots. If a capture selector changes, update the translation or English selector override as appropriate.

## Verification

```sh
npm run check:i18n
npm run build
npm test
npm run build-storybook
npm run check:storybook
npm run check:i18n:browser
npm run check:drive-artifacts
```

`check:i18n` verifies referenced literal keys, matching placeholder counts, and untranslated application literals outside explicit language/parser exceptions. It does not certify translation quality or prove every user flow. Unit/integration tests cover concurrent language isolation, language precedence, English onboarding, voice language/end phrases, generated artifacts, and preservation of owner content. Browser checks cover both languages, English interactions, reload persistence, English manual assets, and file:// exports. Existing nonsecure-HTTP and authorization tests remain applicable.

With Storybook running:

```sh
npm run capture:manual
npm run capture:manual:en
```

Google OAuth, paid Vertex/Gemini inference, real voice recognition, and real Sheets/Drive/Gmail operations require separate credentials and live verification. Mock and browser results do not validate these external services.

## 日本語の補足

翻訳は日本語の原文をキーにして `shared/en.json` に追加します。文中の変数は `{0}`、`{1}` のように指定し、語順を変えられる一文単位を優先します。共有の定数を読み込み時に翻訳すると、同時アクセスやStorybookの切り替えで誤った言語が残るため、関数またはgetterで利用時に解決します。

保存済みの店名・記事・顧客情報を言語切り替えだけで書き換えません。通貨と日時はお店の国・タイムゾーンに従い、言語切り替えでは変わりません。列名・列順・APIの識別子は維持します。切り替えではページを再読み込みするので、未保存の操作は先に保存してください。辞書チェックだけでは操作全体を保証できないため、両言語の画面とAPI、実際のfile://出力も確認します。

## Region verification

`shared/region.ts` defines country/currency, minor-unit conversions and local-time calculations. UI formatting uses a per-shop React context, so previews cannot change another screen's currency or time zone. New shops derive a region default from the browser language and `gemihub_tz` cookie. Explicit language choices do not change the country default; existing shops are never migrated by browser detection.

Run `npm test` for US/JP compatibility, summer-time gaps/repeated hours, Calendar bounds, local date filters, first-visit defaults and USD payment/refund tests. After `npm run build`, run `npm run check:region` for PC/mobile settings, prices, booking dates and offline US exports. Existing browser scripts specify their expected language or use the shop's configured time zone.

# gemihub

[English](README.md) · [日本語](README_ja.md)

**人に頼むのと同じやり方で、AIにお店のシステムを頼める。**

個人商店・サロン向けの予約・店舗運営システムです。設定画面の専門用語を覚える必要はありません。制作担当者に相談するように「こんなお店にしたい」と話し、画面の気になる場所をペンで囲んで「ここを直して」と伝えるだけで、AIが画面案をつくり、確認してから公開できます。

## 画面イメージ

**画面を指さして頼む：** 変更したい箇所をペンで囲んで「ここをこう変えて」と伝え、プレビューで確認してから反映できます。

![変更したい箇所をペンで囲んだ、店主用の画面編集](public/manual/22-pen.jpg)

**お客様が予約する：** メニュー・スタッフ・空き時間を選び、そのまま予約できます。

![メニュー・スタッフ・空き時間と予約内容を確認する、お客様の予約画面](public/manual/07-reservation.jpg)

## なにができるか

### 1. 人に頼むのと同じやり方で、AIにお店づくりを頼める
- **会話でお店を立ち上げ：** 業種やほしい機能をチャットや音声で伝えるだけで、AIが聞き取りながら必要な画面構成を提案します。
- **メモやURLから設定：** お店の基本情報・メニュー・スタッフ・営業時間・予約ルールの「AIで設定」で設定案を作り、確認して入力欄に反映してから保存できます。
- **画面をペンで囲んで「ここを直して」：** プレビュー画面の気になる箇所をペンで丸く囲み、言葉や音声で指示するだけでデザインや文言を修正できます。
- **声やチャットで相談・質問：** 「今のキャンセル規定はどうなってる？」「来月からルールを変えたい」など、お店のアシスタントに音声（Gemini Live）やチャットで相談し、変更の依頼文をまとめてもらえます。
- **写真や記事も言葉で依頼：** メニューやページに使う画像の生成や、ブログ・お知らせ記事の下書き作成もAIに頼めます。

### 2. 予約受付・決済・スタッフ連携
- **柔軟な予約枠計算：** 営業時間・定休日・臨時休業・スタッフのシフト・メニューの所要時間から空き枠を自動で計算します（スタッフ指名・指名なしの両方に対応）。
- **Google カレンダー連携：** 店主ログインでDrive・Gmailと一緒にCalendarの空き状況の許可を取得します。店主のスタッフ登録は不要で、店主の予定を予約枠に自動反映します。追加スタッフ0人でも利用できます。ほかのスタッフはスタッフ用ログインでCalendarを許可します。
- **追加メニュー：** 付替オフやケアを、指定した通常メニューに追加して予約できます。料金と所要時間を合算して空き枠・予約・決済に使い、同じグループの重複選択を防ぎます。
- **曜日別の営業時間：** 通常は19:00、火・金だけ21:00まで、のように曜日ごとに営業時間を変えられます。
- **PayPal 事前決済と自動返金：** 予約時の PayPal 決済と、キャンセル規定（何時間前なら何％返金など）に基づく自動返金に対応しています。
- **キャンセルと返金：** 対象の支払済み予約をキャンセルすると、代わりの予約を自動で受け付け、予約が入れば返金額が増えます。ほかの方の支払い開始前かつ受付期限前なら、元の予約に戻すこともできます。新しく予約する方には「お得に予約できる空き枠」として表示します。
- **AIによるPayPalの確認：** 「相談・質問」で「49.50ドルの返金は完了した？」のように聞くと、AIが読み取り専用のツールでお店自身のPayPalの注文・決済・返金・取引を調べ、予約台帳との違いも含めて答えます。1時間ごとのチェックが、止まっている返金・確定していない決済・状態の不一致・売れ残りそうな割引枠を「要対応」に表示し、緊急のものはすぐ、ほかは1日1回のまとめでメール通知します。対応はサーバーが決めた提案を店主が画面で承認したときだけ実行し、実行前にPayPalの状態を確認し直すので二重に返金しません。AIはPayPalに書き込めず、金額も決めません。
- **お店側の選択：** 「設定 → メニュー・料金」でメニューごとに受付をON／OFFできます（初期値ON）。予約ルール専用の「AIで設定」でも返金率の変更案を確認・保存できます。既定の返金率は24時間前まで100%、12時間前まで70%、1時間前まで40%、以降0%。対象枠の割引は10%・30%・50%で、期限切れ後の出し直しは行いません。手順と画面は、アプリの `/manual#guide-cancellations` を参照してください。

### 3. 日々の店舗運営と顧客管理（CRM）
- **予約・お問い合わせ管理：** 日付やスタッフ別の予約確認に加え、お問い合わせを手動作成し、ひとつの対応フォームで電話・お客様からの連絡・社内メモ・メール返信を切り替え、時系列で残せます。メールは「送信して保存」、その他は記録のみ保存します。一覧／4列のカンバン表示を切り替えて対応状況を管理し、メールが分からない案件も登録できます。お客様フォーム・手動受付・各対応記録で添付でき、返信メールにはその返信用のファイルを送れます（5ファイル・各5MB・合計10MB）。1ヶ月以上前の完了案件は期間を指定すると表示します。
- **AI電話受付：** Twilioの着信をGemini Liveが受け、公開済み設定から営業時間・場所・メニュー・料金をその場で案内します。現金予約はオンラインと同じ空き枠に登録し、お問い合わせは折り返し用に記録します。電話の現金予約は、登録時と同じ番号から期限内にキャンセルできます。オンライン予約はオンラインでの手続きを案内します。非通知には番号通知でのかけ直しを案内します。通話の文字起こしと結果は検索できます。
- **お客様カルテ（CRM）：** 来店履歴や利用金額の自動集計、スタッフ専用の顧客メモ・写真添付・画像ギャラリーを利用できます。
- **会員登録前も含むアクセス集計：** 「お客様」または「ブログ・お知らせ」の「お店のアクセス数」で、7・30・90日の日別PV・ユニークブラウザ数と記事別のアクセス数を確認できます。同じ日の同じブラウザは、複数ページを見ても1件です。ユニークは実人数の目安で、別端末・シークレットモード・保存の削除は別扱いです。店主・スタッフの確認は除外し、ブラウザ保存が使えない閲覧はPVだけに含めます。
- **お客様の行動履歴とAI調査：** お客様詳細の一番下で、ログイン・予約画面・マイページ・支払い開始・予約確定・キャンセル・代わりの予約受付と取り消しを1ページ10件ずつ確認できます。「相談・質問」で「昨日の訪問数は？」「よく読まれた記事は？」「今日のエラーは？」と聞くと、同じ集計とそのお店のアクセス・エラー・PayPalログを根拠付きで調べます。ログはFirestoreに90日保存します。アプリ内マニュアルの `/manual#guide-shop-traffic`・`/manual#guide-article-access`・`/manual#guide-customer-activity` を参照してください。
- **日本語・英語対応：** 管理画面・お客様向け画面・マニュアルを日本語と英語で切り替えられます。
- **JP/US 対応：** お店の通貨・タイムゾーンを表示言語とは独立して選べます。詳細は[言語・地域の説明](docs/i18n.md)を参照してください。

## キャンセルした枠に予約が入ると、返金が増える

対象の支払済み予約をキャンセルすると、その枠を割引価格で自動的に案内します。別の方が予約・決済すると、元のお客様への返金額が増えます。キャンセルの確認時に、返金予定額・別の方が予約した場合の返金額・受付期限を表示します。別の方は、同じお店の予約ページからPayPalで支払います。

既定のキャンセル条件では、次のようになります。

| 来店まで | 通常キャンセルの返金率 | 別の方の予約価格 | 元のお客様の回収率 | 増加分 |
| --- | --- | --- | --- | --- |
| 24時間以上 | 100% | 再案内なし・全額返金 | 100% | — |
| 24〜12時間 | 70% | 10%引き | 90% | +20ポイント |
| 12〜1時間 | 40% | 30%引き | 70% | +30ポイント |
| 1時間未満 | 0% | 半額 | 50% | +50ポイント |

返金の増額は、別の方の予約・決済が成立した場合です。期限までに予約が入らなければ、キャンセル受付時に提示した返金予定額で精算して終了し、時間の経過による減額や次の段階への出し直しはありません。最後の受付は来店10分前までです。受付期限前かつ別の方の支払い開始前なら、キャンセルを取り消して元の予約に戻せます。

PayPalで事前決済済みで、お店が代わりの予約を許可した対象メニューに適用します。率は実際の支払額と予約時に固定された条件に基づき、独自のキャンセル条件では異なる場合があります。たとえば55ドルの予約は、通常の返金予定額が38.50ドルでも、10%引きで別の方が予約すれば49.50ドルの返金になります。詳しい流れは[プロジェクト説明（英語）](docs/about_this.md#cancel-and-recover-more)を参照してください。

## どういう仕組みか

```
[店主 / スタッフ / お客様]
         │
         │ (会話・音声・ペンで囲んだ画面キャプチャで依頼)
         ▼
   [ gemihub サーバー ] ── (意図の理解・変更案作成・画像生成) ──► [ Vertex AI (Gemini) ]
     │            │
     │            ├── (業務データ・セッション・排他ロック) ───────► [ Cloud Firestore ]
     │            └── (生成した公開ページ) ─────────────────────► [ Cloud Storage（非公開）]
     │
     └── (画像・添付・仕様書・書き出しファイル) ────────────► [ 店主の Google Drive ]
```

- **マルチモーダルな対話で画面・記事・設定を提案（予約・決済・権限はサーバーが厳密に管理）：**
  店主が送った「話し言葉」「音声」「ペンで囲んだ画面キャプチャ」を Vertex AI の Gemini が読み取り、ページの構成・文章（Markdown）・デザイン・画像や店舗設定の変更案を作ります。一方、認証や権限境界・空き枠計算・決済金額の計算はサーバー側の固定ロジックで行うため、AIの出力によって予約や決済の安全性が損なわれることはありません。
- **テーマの作成と確認：**
  初回はお店名とロゴの有無を確認し、ブログ・お知らせ・スタッフ紹介・商品やサービス紹介を個別に選べます。AIが参考画像からHTML/CSSでテーマを作成し、独立したAIの確認と修正を最大3回行います。参考ページ画像はデザインの手がかりとし、掲載を依頼したロゴや写真は使います。最初のプレビューから赤ペンで修正できます。
- **ページ全体の編集と、修正後の画面確認：**
  「ページ全体」でヘッダー・中央の枠・フッターをまとめて編集し、中央には仮の内容と分かるDummy表示を置きます。赤ペンと依頼文からAIが修正箇所を自動で判断し、対象を選ぶ操作は不要です。修正後のPC・スマートフォンの実画面をAIが確認し、問題があれば最大2回再修正します。確認済みの案を比較し、「OK」でローカルに採用します。本番への反映は別の操作です。同じチャットの会話を引き継ぎ、説明は初心者向けの言葉にします。
- **根拠（出典）にもとづく相談と、「提案 → プレビュー確認 → 承認」フロー：**
  「相談・質問」では、調査用のLLMがシステムの仕様書・お店の `spec.md`・変更履歴 `history.md`・台帳の実データを調べて出典付きで回答し、書かれていないことは推測せず「書かれていません」と答えます。変更依頼も、店主が画面でプレビューや差分を確認して承認したときだけ本番に反映され、依頼文も `history.md` に記録されます。
- **データの保存と書き出し：**
  設定・予約・顧客情報・お問い合わせ・記事・AIチャットは **Firestore** に保存します。店主は **「公開の設定」** から全体をJSON、記録の種類ごとにCSVで保存できます。画像・添付・仕様書・変更履歴・オフラインHTMLは店主の **Google ドライブ** に残り、書き出しにはファイル本体ではなく参照が含まれます。
- **公開ページは生成済みのHTMLで配信：**
  公開や設定・デザイン・記事の保存のたびに、お店のトップ・固定ページ・記事一覧・記事を日英の完成したHTMLとして生成し、非公開の Cloud Storage バケットに保存します。サーバーが閲覧権限を確認して保存済みのページを返すので、本文の表示に JavaScript やAPIは不要で、検索向けの情報とサイトマップも含みます。CSSと画像は店舗ごとに1回だけ保存し、ブラウザにキャッシュされます。予約・マイページ・お問い合わせは、操作用の画面としてアプリを起動します。

## 環境構築（ローカルで動かす）

Node.js 24 以上が必要です。

認証やクラウド接続なしで、インメモリデータを使ったサロンデモとフォームでの編集を試せます。自由な質問への回答、ペン編集、自然言語での変更には Vertex AI の接続が必要です。

```sh
npm ci
cp .env.example .env
npm run build
npm start
```

http://localhost:3000 を開き、**「サロンのデモを試す」** を選択してください。

Google / Vertex AI を接続する場合や、コードを触る場合（開発サーバー、Storybook、各種チェック）は [docs/development_ja.md](docs/development_ja.md) を見てください。
